1. Для учебного разбора работы службы я взял тестовую службу lab-heartbeat.service с которой работал ранее. 
Команда systemctl status lab-heartbeat.service показала, что на данный момент служба остановлена (inactive), а 
автозапуск службы отключен (disabled).
2. Нужно было понять, что крайняя остановка службы не связана с ошибкой 127, которую мы воспроизвели ранее. Для 
этого были выполнены следующие команды (важно уточнить, что некоторые команды могут быть лишними и просто 
показывают последовательный ход размышлений):

2.1 Для начала проверим сколько записей от systemd у нас вообще имеется. Выполним команду sudo journalctl 
--list-boots. Команда показала 15 загрузок с 13 октябра по 4 ноября. Этого вполне достаточно для расследования.

2.2 Смотрим есть ли записи в текущей и предыдущей загрузки от службы lab-heartbeat.service командой: sudo 
journalctl -u lab-heartbeat.service -b 0 -l --no-pager, где -b 0 выбирает текущую загрузку, а -b -1 предыдущую 
загрузку. Команда показала ответ: -- No entries -- означает, что по заданным фильтрам записей не найдено. Меняем 
аргумент у -b с 0 на -1 и смотрим записи за предыдущую загрузку. Тоже получили результат no entries.

2.3 Тогда смотрим в целом последнии записи от этой службы. Для этого выполняем команду: sudo journalctl -u 
lab-heartbeat.service -n 40 --no-pager -o short-iso (где опция -o short-iso выводит нам время в более 
содержательном формате, пример: 2026-10-31T08:50:38+03:00). Видим, что последняя запись была 
2026-10-31T08:50:38+03:00 и говорит об остановке службы. Но пока не известно, кто остановил службу, пользователь 
или звершение работы операционной системы.

2.4 Проверим, предществовали ли какие-нибудь ошибки ранее. Выполним команду: sudo journalctl -u 
lab-heartbeat.service -o short-iso --no-pager | grep -Ei 'error|failed|no such file|permission denied|exited', 
где -Е мы используем реглуряные выражения, а -i игнорируем регистр. Либо, можно искать ошибки через journalctl. 
Выполним команду: sudo journalctl -u lab-heartbeat.service -g 'No such file|Failed|exited' -o short-iso 
--no-pager. В данном случае -g ищет уже сформированный текст в полях MESSAGE в сообщениях самого журнала. Таким 
образом мы выявили, что служба падала в ошибки и последняя ошибка датировалась 2026-10-30T07:52:59+03:00. 
Сохраним данную информацию в файл командой sudo journalctl -u lab-heartbeat.service --since "2026-10-30 
07:35:00" --until "2026-10-30 08:20:00" -o short-iso --no-pager > reports/history-failure-recovery.txt.

2.5 Далее, ошибка 127 не объясняет нынешнее состояние inactive службы lab-heartbeat.service. Более того, служба 
после ошибки успешно работала. То есть ошибку 127 уже можно исключить, так как работа службы была исправлена, 
запущена и далее ошибок не было до последний записи, когда служба была остановлена 31 октября. Поэтому теперь, 
нам нужно посмотреть события вокруг остановки 31 октября. Для этого выполняем команду: sudo journalctl --since 
"2026-10-31 08:50:30" --until "2026-10-31 08:50:45" -o short-iso --no-pager. Тут мы специально убрали -u 
lab-heartbeat.service, чтоб проверить события других служб вокруг нашей службы.

2.6 После выполнения последней команды, мы увидели, что была выполнена команда sudo systemctl stop 
lab-heartbeat.service пользователем denis, а через секунду служба штатно остановилась. Причину состояния 
disabled мы установим отдельно. Команда stop не объясеняет ее отключение. Записываем фрагмент лога в файл 
reports/history-stop-context.txt командой sudo journalctl --since "2026-10-31 08:50:30" --until "2026-10-31 
08:50:45" -o short-iso --no-pager > reports/history-stop-context.txt.

2.7 Теперь определим команду отключения автозапуска. Для этого выполняем команду: sudo journalctl _COMM=sudo 
--since "2026-10-31 08:45:00" -g 'lab-heartbeat' -o short-iso --no-pager. Где: _COMM=sudo выбирает записи 
процесса sudo, а -g 'lab-heartbeat' оставляет строки содержащие lab-heartbeat в полях MESSAGE. После выполнения 
команды видно, что в 08:50:37 sudo записал выполнение команды stop, а в 08:50:38 systemd подтвердил штатную 
остановку. Данное действие мы установили в пункте 2.6. Далее в 08:52:36 был выключен автозапуск службы 
командой systemctl disable lab-heartbeat.service. Еще в 08:53:10 был открыт unit файл службы в редакторе 
командой nano /etc/systemd/system/lab-heartbeat.service. Таким образом мы установили, что служба была 
остановлена пользователем denis, а так же этим же пользователем отключен автозапуск. Сохраняем прошлые действия 
в файл командой: sudo journalctl _COMM=sudo --since "2026-10-31 08:45:00" --until "2026-10-31 09:00:00" -g 
'lab-heartbeat' -o short-iso --no-pager > reports/history-admin-actions.txt.

2.8 Открытие редактора само по себе не доказывает изменение unit файла. Поэтому нужно проверить, в каком 
состоянии файл находится сейчас, перед запуском службы. Выполняем команду systemctl cat lab-heartbeat.service. И 
видим, что путь до скрипта указан верно. Так же проверим скрипт не содержит синтаксических ошибок, выполним 
команду: bash -n /home/denis/linux-admin-lab/04-systemd-service/scripts/lab-heartbeat.sh. Опция -n говорит о 
том, будет проверен синтаксис без выполнения скрипта. Отдельно проверим, что у пользователя denis есть право на 
чтение скрипта, выполним команду: ls -l /home/denis/linux-admin-lab/04-systemd-service/scripts/lab-heartbeat.sh. 
Сохраним конфигурацию в файл командой: systemctl cat lab-heartbeat.service > reports/unit-initial.txt.

2.9 Проверим запуск, отделим новые события от прошлой ошибки 127. Право x на выполнение файла lab-heartbeat.sh 
нам не нужно, потому что запуск будет происходить напрямую через /bin/bash. Выполним команду: CHECK_START=$(date 
--iso-8601=seconds) ; sudo systemctl start lab-heartbeat.service, подождем 15 секунд и выполним команду sudo 
journalctl -u lab-heartbeat.service --since "$CHECK_START" -o short-iso --no-pager. Переменная CHECK_START 
хранит время начала проверки: переменная задана перед sudo systemctl start. Время запуска - 6 ноября 
в 08:08:41 МСК, которое видно в статусе и журнале. По журналу мы видим, что служба работает. Команда systemctl 
status lab-heartbeat.service -l --no-pager так же показывает, что служба запущена. Сохраним проверки в файлы 
командами: systemctl status lab-heartbeat.service --no-pager -l > reports/status-check.txt и sudo journalctl -u 
lab-heartbeat.service --since "$CHECK_START" -o short-iso --no-pager > reports/journal-check.txt.

3. 31 октября служба штатно остановилась после команды пользователя denis, автозапуск был отключен отдельно, а 
контрольный запуск 6 ноября подтвердил, что текущая конфигурация работает.

4. Контрольный запуск подтвердил, что служба работает с текущей конфигурацией: systemctl status показал active 
(running), а в журнале появились новые сообщения скрипта.

5. Открытие редактора nano не доказывает, что файл был изменен.
